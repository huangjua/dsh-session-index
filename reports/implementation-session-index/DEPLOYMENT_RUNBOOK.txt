6. 在自然使用产生追加之后短时观察一次增量 readBytes/deltaBytes/deltaParsed 与 FTS 提交收敛，
   不强行改写真实会话或force所有生产来源。无自然追加则记待观察，不虚报完成。
7. 保存生产验收时间、加载版本/hash、健康字段和迁移统计；完成清单满足后才把 S7 写为已部署。

八、回滚（始终保护上线后新增的用户书签）

1. 获批范围内停止全部共享写方并防自动重启。先将当前完整 dataDir 保存为新的 data-after-candidate
   离线快照，特别保存上线后 bookmarks.jsonl 与其 hash；不得以 before 快照直接覆盖新增书签。
2. 将失败候选 lib/package/README 保存在独立目录，按第六节同样核验的绝对路径执行移动/恢复；
   恢复 code snapshot 的完整 lib 与旧 package/README，核对其 hash。不能混用新worker与旧入口。
3. 旧 0.0.2 只认识 v1，不能直接让它读写候选 v2 书签。回滚数据策略必须在恢复旧写方前选择：
   a. 若候选上线后没有任何新增/更新用户书签，且当前 sidecar hash/全物理行与已记录迁移结果能证明
      只有本次格式转换，才可恢复 before 书签；保留 after 快照。
   b. 若有新增/更新或无法证明没有变化，保留 after 书签为用户权威数据。先在离线工作副本合并/转换
      并逐物理行核验。不把新 anchorId 反推成旧 numeric，不丢新记录；旧版不能表达的新书签仍要
      保全为独立可读存档，说明限制，并在用户确认具体兼容方案前禁止旧书签写方启动。
4. 派生 FTS 可以从 before 一致快照恢复（db与其WAL/SHM整组一致），或在保全 before/after 后走获批
   重建；index.json 的游标也必须匹配或让旧版安全重新对账。禁止只恢复 fts.db 主文件混入另一时点WAL。
   任何移走现有生产目录均先核验绝对目标正是批准的 productionDataRoot，保存after再移动，不能
   删除用户数据、盲目覆盖整个 dataDir，不能依据遗留 spool owner 诊断自动清理。
5. 恢复授权宿主，按第七节的旧版本适用字段只读验收；记录回滚版本、原因、数据策略与仍保留的新书签。
   before/after 快照和 lib.before 目录清理由用户单独批准，本 runbook 不执行清理。

九、推送与本轮交付边界

本轮仅候选开发和发布准备。S7 生产 dry-run/apply、部署、宿主停止/重启和生产验收命令没有运行；
生产书签数量/可恢复数量目前未知。S7 授权不足时保留上述具体执行单，不能标成已完成生产发布。
git push、远端发布、npm/市场发布不包含在部署授权中；只有用户独立授权后才执行。
